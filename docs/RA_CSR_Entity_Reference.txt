================================================================================
  A1. users
================================================================================

  Purpose:
    Master user registry. Stores AD/LDAP profile data and account status.
    Authentication is handled externally by AD/LDAP — NO passwords stored.
    Rows are auto-created on first AD login via UserManagementService.

  Used By:
    - certificate_requests.requester_id (who submitted the CSR)
    - certificate_request_approvals.approver_id (who approved/rejected)
    - audit_log.user_id (who performed the action)
    - user_roles.user_id (role assignments)
    - approval_delegations (delegation of authority)
    - key_recovery_requests (who requested key recovery)
    - All controllers via AbstractSecuredController (identity resolution)

  +---------------------+---------------+------+-----+------------------------+
  | Column              | Type          | Null | Key | Purpose                |
  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | username            | VARCHAR(100)  | NO   | UQ  | AD sAMAccountName      |
  | email               | VARCHAR(200)  | YES  |     | User's email address   |
  | full_name           | VARCHAR(200)  | YES  |     | Full legal name        |
  | display_name        | VARCHAR(200)  | YES  |     | Display/preferred name |
  | is_active           | BOOLEAN       | NO   |     | FALSE = soft-deleted   |
  | last_login_at       | DATETIME(6)   | YES  |     | Last successful login  |
  | created_at          | DATETIME(6)   | NO   |     | Record creation time   |
  | created_by          | VARCHAR(100)  | NO   |     | Who created this user  |
  | updated_at          | DATETIME(6)   | NO   |     | Last modification time |
  | updated_by          | VARCHAR(100)  | NO   |     | Who last modified      |
  +---------------------+---------------+------+-----+------------------------+

  Indexes:
    idx_users_is_active      (is_active)
    idx_users_last_login_at  (last_login_at)

  Constraints:
    uq_users_username        UNIQUE (username)

  Seed Data:
    system / System Scheduler
    admin  / PKI RA Admin

  A2. roles
================================================================================

  Purpose:
    Master list of all defined roles in the PKI-RA system.
    Each role represents a named permission set.
    Users are linked to roles via user_roles junction table.
    Used by Spring Security for RBAC (role-based access control).

  Used By:
    - user_roles.role_id (assign roles to users)
    - template_permissions.role_id (which roles can use which templates)
    - RaSecurityConfig (endpoint protection rules)
    - AdminSecurityConfig (admin endpoint protection)

  +---------------------+---------------+------+-----+------------------------+
  | Column              | Type          | Null | Key | Purpose                |
  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | role_name           | VARCHAR(50)   | NO   | UQ  | Role identifier        |
  |                     |               |      |     | e.g. ROLE_ADMIN        |
  | description         | VARCHAR(500)  | YES  |     | Human-readable desc    |
  | is_active           | BOOLEAN       | NO   |     | FALSE = disabled       |
  | created_at          | DATETIME(6)   | NO   |     | Record creation time   |
  | created_by          | VARCHAR(100)  | NO   |     | Who created            |
  | updated_at          | DATETIME(6)   | NO   |     | Last modification      |
  | updated_by          | VARCHAR(100)  | NO   |     | Who last modified      |
  +---------------------+---------------+------+-----+------------------------+

  Seed Data:
    ROLE_ADMIN     — Full system access
    ROLE_OPERATOR  — Certificate operations (request, approve, revoke)
    ROLE_AUDITOR   — Read-only audit logs and reports
    ROLE_VIEWER    — Read-only configs and status

  Future Roles (added in later phases):
    ROLE_RA_OFFICER         — Phase 5 (advanced approvals)
    ROLE_KEY_RECOVERY_AGENT — Phase 9 (dual-control key recovery)


================================================================================
  A3. user_roles
================================================================================

  Purpose:
    Many-to-many junction table linking users to roles.
    One user can hold multiple roles; one role can be held by many users.
    UNIQUE(user_id, role_id) prevents duplicate assignments.

  Used By:
    - UserManagementService (assign/remove roles)
    - Spring Security (role resolution during authentication)
    - Template permission checks (Phase 2)

  +---------------------+---------------+------+-----+------------------------+
  | Column              | Type          | Null | Key | Purpose                |
  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | user_id             | BIGINT        | NO   | FK  | --> users.id           |
  | role_id             | BIGINT        | NO   | FK  | --> roles.id           |
  | assigned_at         | DATETIME(6)   | NO   |     | When role was assigned |
  | assigned_by         | VARCHAR(100)  | NO   |     | Who assigned the role  |
  +---------------------+---------------+------+-----+------------------------+

  Constraints:
    uq_user_roles        UNIQUE (user_id, role_id)
    fk_user_roles_user   --> users.id  ON DELETE CASCADE
    fk_user_roles_role   --> roles.id  ON DELETE CASCADE

  A4. app_config
================================================================================

  Purpose:
    Stores runtime application configuration as flat key-value rows.
    Each row holds one field value (plain string — no JSON).
    Rows are grouped by config_type and assembled into a typed DTO
    by ConfigBean on ApplicationReadyEvent.
    Supports hot-reload via POST /api/admin/config/refresh.

  Used By:
    - ConfigBean (loads into in-memory cache at startup)
    - AbstractRefreshController (hot-reload without restart)
    - Notification settings (Phase 4)
    - CA connector configs (Phase 8, supplementary)

  +---------------------+---------------+------+-----+------------------------+

  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | config_key          | VARCHAR(100)  | NO   |     | Field name (e.g. host) |
  | config_type         | VARCHAR(50)   | NO   |     | Group (e.g. LDAP)      |
  | config_value        | VARCHAR(500)  | NO   |     | Plain string value     |
  | description         | VARCHAR(500)  | YES  |     | Human-readable label   |
  | is_active           | BOOLEAN       | NO   |     | FALSE = excluded       |
  | created_at          | DATETIME(6)   | NO   |     | Record creation time   |
  | created_by          | VARCHAR(100)  | NO   |     | Who created            |
  | updated_at          | DATETIME(6)   | NO   |     | Last modification      |
  | updated_by          | VARCHAR(100)  | NO   |     | Who last modified      |
  +---------------------+---------------+------+-----+------------------------+

  Constraints:
    uq_app_config_key_type  UNIQUE (config_key, config_type)

  Config Types (Seed):
    LDAP — host, port, baseDn, bindDn, bindPassword, useSsl, timeouts


================================================================================
  A5. error_catalog
================================================================================

  Purpose:
    Stores all application error codes and messages in the database.
    Enables error message changes without code deployment.
    SECURITY: internal_code (logs only) vs external_code (API response).
    Cached by ErrorCatalogBean at startup with hot-reload support.
    Validated by ErrorCatalogStartupValidator against RaErrorCode enum.

  Used By:
    - ErrorCatalogBean (in-memory cache, indexed by internal + external code)
    - ExceptionFactory (creates AppException from error code)
    - AbstractGlobalExceptionHandler (8 exception handlers use fallback codes)
    - ErrorCatalogStartupValidator (validates all enum codes exist at boot)

  +---------------------+---------------+------+-----+------------------------+
  | Column              | Type          | Null | Key | Purpose                |
  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | internal_code       | VARCHAR(50)   | NO   | UQ  | App-internal code      |
  |                     |               |      |     | e.g. PKI_CERT_001      |
  | external_code       | VARCHAR(50)   | NO   | UQ  | User-facing code       |
  |                     |               |      |     | e.g. ERR-001           |
  | message             | VARCHAR(500)  | NO   |     | User-facing message    |
  | description         | VARCHAR(1000) | YES  |     | Internal description   |
  |                     |               |      |     | (logs only, never API) |
  | category            | VARCHAR(50)   | NO   |     | CERTIFICATE, AUTH,     |
  |                     |               |      |     | VALIDATION, NETWORK,   |
  |                     |               |      |     | SYSTEM                 |
  | severity            | VARCHAR(20)   | NO   |     | INFO/WARNING/ERROR/    |
  |                     |               |      |     | CRITICAL               |
  | http_status         | INT           | NO   |     | HTTP status code       |
  | is_retryable        | BOOLEAN       | NO   |     | Client can retry?      |
  | is_active           | BOOLEAN       | NO   |     | FALSE = excluded       |
  | created_at          | DATETIME(6)   | NO   |     | Record creation time   |
  | created_by          | VARCHAR(100)  | NO   |     | Who created            |
  | updated_at          | DATETIME(6)   | NO   |     | Last modification      |
  | updated_by          | VARCHAR(100)  | NO   |     | Who last modified      |
  +---------------------+---------------+------+-----+------------------------+

  Seed Data: 14 error codes across 5 categories
    PKI_CERT_001..005  — Certificate errors (404, 400, 500, 409, 500)
    PKI_AUTH_001..003  — Authentication errors (401, 403, 401)
    PKI_VAL_001..002   — Validation errors (400, 400)
    PKI_NET_001..002   — Network errors (503, 503)
    PKI_SYS_001..002   — System errors (500, 503)


================================================================================
  A6. audit_log
================================================================================

  Purpose:
    Immutable audit trail for every significant RA operation.
    One row per action — NEVER updated or deleted.
    Written by AuditLogService with REQUIRES_NEW propagation so
    audit rows survive even if the calling transaction rolls back.

  Used By:
    - AuditLogService (write path — every controller action)
    - AuditController (read path — filtered search, summaries)
    - AuditLogSpecification (Specification pattern for composable queries)
    - SIEM integration (Phase 12 — forward to external systems)
    - Reporting dashboard (Phase 6)

  +---------------------+---------------+------+-----+------------------------+
  | Column              | Type          | Null | Key | Purpose                |
  +---------------------+---------------+------+-----+------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID      |
  | username            | VARCHAR(100)  | NO   | IDX | Who (AD sAMAccountName)|
  | user_id             | BIGINT        | YES  | FK  | --> users.id (nullable |
  |                     |               |      |     | for pre-user actions)  |
  | action              | VARCHAR(100)  | NO   | IDX | What (CSR_SUBMIT,      |
  |                     |               |      |     | CERT_APPROVE, etc.)    |
  | resource_id         | VARCHAR(200)  | YES  | IDX | Which resource affected|
  | description         | VARCHAR(1000) | YES  |     | Human-readable summary |
  | ip_address          | VARCHAR(50)   | YES  |     | Client IP (X-Fwd-For) |
  | outcome             | VARCHAR(20)   | NO   |     | SUCCESS or FAILURE     |
  | created_at          | DATETIME(6)   | NO   | IDX | When (immutable)       |
  +---------------------+---------------+------+-----+------------------------+

  Constraints:
    chk_audit_log_outcome  CHECK (outcome IN ('SUCCESS', 'FAILURE'))
    fk_audit_log_user      --> users.id ON DELETE SET NULL

  Key Design:
    - NO updated_at / updated_by (immutable — insert only)
    - REQUIRES_NEW transaction (survives caller rollback)
    - user_id is nullable (for system/scheduler actions)

================================================================================
  B1. certificate_requests
================================================================================

  Purpose:
    Stores every CSR (Certificate Signing Request) submitted to the RA.
    Tracks the complete lifecycle of each request from PENDING through
    approval/rejection to issuance or failure. This is the central table
    of the entire RA system — every certificate starts here.

  Lifecycle:
    PENDING --> APPROVED --> ISSUED     (happy path)
    PENDING --> REJECTED                (denied by operator)
    PENDING --> APPROVED --> FAILED     (CA signing error)

  Used By:
    - CertificateLifecycleService (submit, approve, reject, issue)
    - CertificateRequestController (REST API endpoints)
    - certificate_request_approvals (approval decisions reference this)
    - certificates.request_id (issued cert links back here)
    - Reporting dashboard (Phase 6 — request counts, trends)
    - Approval workflow engine (Phase 5 — multi-level chains)
    - Duplicate detection (Layer 7 validation — csr_hash lookup)

  +-------------------------+---------------+------+-----+------------------------+
  | Column                  | Type          | Null | Key | Purpose                |
  +-------------------------+---------------+------+-----+------------------------+
  | id                      | BIGINT        | NO   | PK  | Auto-increment ID      |
  | csr_pem                 | TEXT          | NO   |     | Full PKCS#10 CSR in    |
  |                         |               |      |     | PEM format (preserved  |
  |                         |               |      |     | for re-signing, audit) |
  | subject_dn              | VARCHAR(500)  | NO   | IDX | Parsed Subject DN from |
  |                         |               |      |     | CSR, e.g. CN=api.      |
  |                         |               |      |     | example.com,O=Acme,C=IN|
  | key_algorithm           | VARCHAR(20)   | NO   |     | CSR public key algo    |
  |                         |               |      |     | RSA, ECDSA, Ed25519    |
  | key_size                | INT           | NO   |     | Key size in bits       |
  |                         |               |      |     | e.g. 2048, 4096, 256   |
  | subject_alt_names       | VARCHAR(2000) | YES  |     | Comma-separated SANs   |
  |                         |               |      |     | extracted from CSR or  |
  |                         |               |      |     | provided by requester  |
  | requested_validity_days | INT           | YES  |     | Requested cert lifetime|
  |                         |               |      |     | NULL = use default     |
  | status                  | VARCHAR(20)   | NO   | IDX | Request lifecycle state|
  |                         |               |      |     | PENDING / APPROVED /   |
  |                         |               |      |     | REJECTED / ISSUED /    |
  |                         |               |      |     | FAILED                 |
  | status_reason           | VARCHAR(1000) | YES  |     | Rejection reason or    |
  |                         |               |      |     | failure error message  |
  | requester_id            | BIGINT        | NO   | FK  | --> users.id           |
  |                         |               |      | IDX | Who submitted this CSR |
  | certificate_id          | BIGINT        | YES  | FK  | --> certificates.id    |
  |                         |               |      |     | Populated after issue  |
  | created_at              | DATETIME(6)   | NO   | IDX | Submission timestamp   |
  | created_by              | VARCHAR(100)  | NO   |     | Audit: who created     |
  | updated_at              | DATETIME(6)   | NO   |     | Last status change     |
  | updated_by              | VARCHAR(100)  | NO   |     | Audit: who modified    |
  +-------------------------+---------------+------+-----+------------------------+

  Indexes:
    idx_cert_req_status     (status)          — filter by lifecycle state
    idx_cert_req_requester  (requester_id)    — "my requests" queries
    idx_cert_req_subject    (subject_dn(255)) — duplicate DN detection
    idx_cert_req_created    (created_at)      — chronological ordering

  Constraints:
    fk_cert_req_requester    --> users.id ON DELETE RESTRICT
    fk_cert_req_certificate  --> certificates.id ON DELETE SET NULL
    chk_cert_req_status      CHECK (status IN ('PENDING','APPROVED',
                                    'REJECTED','ISSUED','FAILED'))

  Future Columns (planned):
    csr_hash         VARCHAR(64)  — SHA-256 of CSR bytes (Phase 1 enhancement,
                                    Layer 7 duplicate detection)
    template_id      BIGINT FK    — --> certificate_templates.id (Phase 2)
    protocol         VARCHAR(20)  — REST/EST/SCEP/CMP (Phase 7)
    validation_warnings  JSON     — warnings from 7-layer validation
    validation_flags     JSON     — flags requiring manual review


================================================================================
  B2. certificates
================================================================================

  Purpose:
    Stores every X.509 certificate issued by the RA/CA system.
    Acts as the serial number registry — every serial is globally unique.
    Tracks certificate lifecycle from ACTIVE through revocation/expiry.
    Contains the full PEM certificate and chain for download.

  Lifecycle:
    ACTIVE --> REVOKED     (revocation by admin/operator)
    ACTIVE --> SUSPENDED   (temporary hold, can be unsuspended)
    ACTIVE --> EXPIRED     (not_after passed, marked by cleanup job)
    SUSPENDED --> ACTIVE   (unsuspended)
    SUSPENDED --> REVOKED  (permanently revoked while held)

  Used By:
    - CertificateLifecycleService (issue, query, download)
    - CertificateRequestController (GET /certificates/{serial})
    - certificate_requests.certificate_id (links request to issued cert)
    - certificate_revocations (Phase 3 — revocation records)
    - certificate_sans (supporting table — SAN lookup)
    - certificate_public_key_hashes (supporting — key reuse detection)
    - CRL generation (Phase 3 — include revoked certs in CRL)
    - OCSP responder (Phase 3 — certificate status lookup)
    - Notification system (Phase 4 — expiry tracking)
    - Reporting dashboard (Phase 6 — cert inventory)
    - LDAP publishing (Phase 10 — publish to AD)
    - Compliance checks (Phase 12 — policy violations)

  +---------------------+---------------+------+-----+---------------------------+
  | Column              | Type          | Null | Key | Purpose                   |
  +---------------------+---------------+------+-----+---------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID         |
  | serial_number       | VARCHAR(64)   | NO   | UQ  | Hex uppercase serial      |
  |                     |               |      |     | e.g. 4F2A1B3C...          |
  |                     |               |      |     | 128-bit random generated  |
  | subject_dn          | VARCHAR(500)  | NO   | IDX | Certificate Subject DN    |
  | issuer_dn           | VARCHAR(500)  | NO   |     | Issuing CA's DN           |
  | not_before          | DATETIME(6)   | NO   |     | Validity start (UTC)      |
  | not_after           | DATETIME(6)   | NO   | IDX | Validity end (UTC)        |
  |                     |               |      |     | Used for expiry tracking  |
  | certificate_pem     | TEXT          | NO   |     | Full PEM-encoded cert     |
  | certificate_chain   | TEXT          | NO   |     | Full PEM chain:           |
  |                     |               |      |     | end-entity + intermediate |
  |                     |               |      |     | + root CA                 |
  | key_algorithm       | VARCHAR(20)   | NO   |     | RSA, ECDSA, Ed25519       |
  | key_size            | INT           | NO   |     | Key size in bits          |
  | signature_algorithm | VARCHAR(50)   | NO   |     | e.g. SHA256withRSA        |
  | status              | VARCHAR(20)   | NO   | IDX | ACTIVE / REVOKED /        |
  |                     |               |      |     | EXPIRED / SUSPENDED       |
  | fingerprint_sha256  | VARCHAR(64)   | NO   | UQ  | SHA-256 of DER cert bytes |
  |                     |               |      |     | for quick identity lookup |
  | request_id          | BIGINT        | YES  | FK  | --> certificate_requests  |
  |                     |               |      | IDX | .id (source request)      |
  | created_at          | DATETIME(6)   | NO   |     | Issuance timestamp        |
  | created_by          | VARCHAR(100)  | NO   |     | Audit: who issued         |
  | updated_at          | DATETIME(6)   | NO   |     | Last status change        |
  | updated_by          | VARCHAR(100)  | NO   |     | Audit: who modified       |
  +---------------------+---------------+------+-----+---------------------------+

  Indexes:
    idx_cert_status     (status)          — filter active/revoked/expired
    idx_cert_subject    (subject_dn(255)) — search by subject
    idx_cert_not_after  (not_after)       — expiry queries, cleanup job
    idx_cert_request    (request_id)      — link back to source request

  Constraints:
    uq_cert_serial       UNIQUE (serial_number)
    uq_cert_fingerprint  UNIQUE (fingerprint_sha256)
    fk_cert_request      --> certificate_requests.id ON DELETE SET NULL
    chk_cert_status      CHECK (status IN ('ACTIVE','REVOKED',
                                'EXPIRED','SUSPENDED'))

  Future Columns (planned):
    public_key_hash    VARCHAR(64)  — SHA-256 of SubjectPublicKeyInfo DER
                                      (key reuse detection, Layer 5)
    ca_connector_id    BIGINT FK    — which CA backend issued it (Phase 8)
    ct_precert_sct     TEXT         — Certificate Transparency SCT (Phase 12)


================================================================================
  B3. certificate_request_approvals
================================================================================

  Purpose:
    Records every approval or rejection decision for certificate requests.
    Each row represents one decision by one approver.
    In Phase 1: single-level approval (one approver per request).
    In Phase 5: multi-level approval chains (multiple rows per request).
    Immutable once created — decisions cannot be changed after the fact.

  Used By:
    - CertificateLifecycleService (approve/reject flow)
    - CertificateRequestController (approval endpoints)
    - CertificateRequestDto (includes approval history)
    - Advanced approval workflows (Phase 5 — chain validation)
    - Reporting (Phase 6 — approval turnaround time)

  +---------------------+---------------+------+-----+---------------------------+
  | Column              | Type          | Null | Key | Purpose                   |
  +---------------------+---------------+------+-----+---------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID         |
  | request_id          | BIGINT        | NO   | FK  | --> certificate_requests   |
  |                     |               |      | IDX | .id (which request)       |
  | approver_id         | BIGINT        | NO   | FK  | --> users.id              |
  |                     |               |      | IDX | (who decided)             |
  | decision            | VARCHAR(20)   | NO   |     | APPROVED or REJECTED      |
  | comment             | VARCHAR(1000) | YES  |     | Approver's note/reason    |
  | created_at          | DATETIME(6)   | NO   | IDX | Decision timestamp        |
  | created_by          | VARCHAR(100)  | NO   |     | Audit: who created        |
  | updated_at          | DATETIME(6)   | NO   |     | (should never change)     |
  | updated_by          | VARCHAR(100)  | NO   |     | (should never change)     |
  +---------------------+---------------+------+-----+---------------------------+

  Constraints:
    fk_approval_request   --> certificate_requests.id ON DELETE CASCADE
    fk_approval_approver  --> users.id ON DELETE RESTRICT
    chk_approval_decision CHECK (decision IN ('APPROVED', 'REJECTED'))

  Future Columns (planned):
    approval_level   INT          — which level in the chain (Phase 5)
    delegated_from   BIGINT FK    — original approver if delegated (Phase 5)

================================================================================
  D1. certificate_revocations
================================================================================

  Purpose:
    Records every certificate revocation event with RFC 5280 reason code.
    Each revoked/suspended certificate has exactly one row here.
    Used by CRL generation job to build the revocation list.
    Used by OCSP responder to answer certificate status queries.

  RFC 5280 Reason Codes:
    0 = unspecified
    1 = keyCompromise
    2 = cACompromise
    3 = affiliationChanged
    4 = superseded
    5 = cessationOfOperation
    6 = certificateHold (suspension — can be unsuspended)

  Used By:
    - CRL generation (Phase 3 — include in CRL)
    - OCSP responder (Phase 3 — status lookup)
    - Key reuse detection (Layer 5 — reason=keyCompromise blocks reuse)
    - Compliance reporting (Phase 12)

  +---------------------+---------------+------+-----+---------------------------+
  | Column              | Type          | Null | Key | Purpose                   |
  +---------------------+---------------+------+-----+---------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID         |
  | certificate_id      | BIGINT        | NO   | FK  | --> certificates.id       |
  |                     |               |      | UQ  | One revocation per cert   |
  | reason_code         | INT           | NO   |     | RFC 5280 reason (0-6)     |
  | reason_text         | VARCHAR(100)  | NO   |     | Human-readable reason     |
  |                     |               |      |     | e.g. "keyCompromise"      |
  | revocation_time     | DATETIME(6)   | NO   |     | When revocation occurred  |
  | invalidity_date     | DATETIME(6)   | YES  |     | When key was actually     |
  |                     |               |      |     | compromised (may differ   |
  |                     |               |      |     | from revocation_time)     |
  | revoked_by          | BIGINT        | NO   | FK  | --> users.id              |
  |                     |               |      |     | Who performed revocation  |
  | created_at          | DATETIME(6)   | NO   |     | Record creation time      |

  | updated_at          | DATETIME(6)   | NO   |     | Last update (unsuspend)   |

================================================================================
  J1. key_escrow
================================================================================

  Purpose:
    Stores encrypted copies of private keys for recovery-eligible
    certificates. Only templates with key_escrow_enabled=true generate
    escrow entries. Private keys are encrypted with a key-encryption-key
    (KEK) before storage — never stored in plaintext.

    - Access requires ROLE_KEY_RECOVERY_AGENT

  |                     |               |      |     | used for encryption       |
  | key_algorithm       | VARCHAR(20)   | NO   |     | RSA / ECDSA (of the       |
  |                     |               |      |     | escrowed key)             |
  | iv                  | VARCHAR(64)   | NO   |     | AES-GCM initialization    |
  |                     |               |      |     | vector (hex)              |

================================================================================
  J2. key_recovery_requests
================================================================================

  Purpose:
    Workflow table for key recovery — dual-control approval required.
    Requester submits recovery request, two different agents must approve
    before the encrypted key is released. Prevents single-person access
    to escrowed private keys.

  Workflow:
    REQUESTED --> APPROVED_1 (first agent approves)
              --> APPROVED_2 (second agent approves) --> RELEASED
              --> REJECTED (any agent rejects)
              --> EXPIRED (not approved within 24 hours)

  +---------------------+---------------+------+-----+---------------------------+
  | Column              | Type          | Null | Key | Purpose                   |
  +---------------------+---------------+------+-----+---------------------------+
  | id                  | BIGINT        | NO   | PK  | Auto-increment ID         |
  | escrow_id           | BIGINT        | NO   | FK  | --> key_escrow.id         |
  | requester_id        | BIGINT        | NO   | FK  | --> users.id (who asked)  |
  | reason              | VARCHAR(500)  | NO   |     | Why recovery is needed    |
  | status              | VARCHAR(20)   | NO   |     | REQUESTED / APPROVED_1 /  |
  |                     |               |      |     | APPROVED_2 / RELEASED /   |
  |                     |               |      |     | REJECTED / EXPIRED        |
  | approver_1_id       | BIGINT        | YES  | FK  | --> users.id (1st agent)  |
  | approver_1_at       | DATETIME(6)   | YES  |     | When 1st agent decided    |
  | approver_2_id       | BIGINT        | YES  | FK  | --> users.id (2nd agent)  |
  | approver_2_at       | DATETIME(6)   | YES  |     | When 2nd agent decided    |
  | released_at         | DATETIME(6)   | YES  |     | When key was released     |
  | expires_at          | DATETIME(6)   | NO   |     | Auto-expire if not done   |
  | created_at          | DATETIME(6)   | NO   |     | Request creation time     |
  | created_by          | VARCHAR(100)  | NO   |     | Who requested             |
  +---------------------+---------------+------+-----+---------------------------+

  Constraints:
    fk_kr_escrow      --> key_escrow.id ON DELETE RESTRICT
    fk_kr_requester   --> users.id ON DELETE RESTRICT
    fk_kr_approver1   --> users.id ON DELETE RESTRICT
    fk_kr_approver2   --> users.id ON DELETE RESTRICT
    chk_diff_agents   approver_1_id != approver_2_id (enforced in code)
    chk_not_self      requester_id != approver_1_id AND
                      requester_id != approver_2_id (enforced in code)
