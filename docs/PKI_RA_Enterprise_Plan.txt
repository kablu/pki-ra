================================================================================
  CONTEXT
================================================================================

  The pki-ra project currently has foundational infrastructure:
    - User Management (AD-synced, RBAC with ROLE_ADMIN)
    - Role Management (roles, user_roles M:M)
    - AppConfig (key-value config with hot-reload cache)
    - Error Catalog (18+ error codes, internal/external separation)
    - Audit Logging (immutable trail, filtered search, summaries)
    - Exception Handling (8 handlers, correlationId, zero leaks)
    - CA Service basics (CSR signing, root/intermediate cert endpoints)

  Goal: Develop into a full enterprise RA comparable to EJBCA, Venafi,
        or Sectigo — certificate lifecycle, approval workflows,
        revocation, protocol support, and multi-CA connectivity.

  Design Patterns in Use:
    - Template Method    (Abstract controllers)
    - Provider Pattern   (ErrorCatalogProvider)
    - Specification      (AuditLog filtering)
    - Strategy           (CaClient interface for multi-CA)
    - Startup Validation (Error codes verified at boot)

  PHASE 1: CERTIFICATE LIFECYCLE CORE                    [Size: XL] [CRITICAL]
================================================================================

  Goal: End-to-end CSR submission -> approval -> issuance -> download

  +-----------------------------------------------------------------------+
  | NEW TABLES                                                            |
  +-----------------------------------+-----------------------------------+
  | certificate_requests              | CSR blob, subject DN, requester,  |
  |                                   | status (PENDING / APPROVED /      |
  |                                   | REJECTED / ISSUED / FAILED),      |
  |                                   | template_id FK                    |
  +-----------------------------------+-----------------------------------+
  | certificates                      | serial, subject, issuer,          |
  |                                   | not_before, not_after, PEM,       |
  |                                   | status (ACTIVE / REVOKED /        |
  |                                   | EXPIRED / SUSPENDED),             |
  |                                   | fingerprint_sha256, request_id FK |
  +-----------------------------------+-----------------------------------+
  | certificate_request_approvals     | request_id FK, approver_id FK,    |
  |                                   | decision, comment, timestamp      |
  +-----------------------------------+-----------------------------------+

  +-----------------------------------------------------------------------+
  | NEW REST APIs                                                         |
  +--------+--------------------------------------+-----------------------+
  | Method | Path                                 | Purpose               |
  +--------+--------------------------------------+-----------------------+
  | POST   | /api/ra/requests                     | Submit CSR            |
  | GET    | /api/ra/requests/{id}                | Get request status    |
  | GET    | /api/ra/requests                     | List requests (paged) |
  | POST   | /api/ra/requests/{id}/approve        | Approve (OPERATOR)    |
  | POST   | /api/ra/requests/{id}/reject         | Reject with reason    |
  | GET    | /api/ra/certificates/{serial}        | Get cert details      |
  | GET    | /api/ra/certificates/{serial}/download| Download PEM/DER/P12  |
  +--------+--------------------------------------+-----------------------+

  Flow:
    User submits CSR --> PENDING --> Operator approves --> CA signs --> ISSUED
                                --> Operator rejects  --> REJECTED
                                --> CA fails          --> FAILED

  Reuse:
    - CertificateIssuanceService (caservice) -- called after approval
    - AuditLogService            -- log every request/approval/issuance
    - BaseAuditEntity            -- extend for new entities
    - ErrorCodeKey               -- add codes PKI_CERT_001 to PKI_CERT_010
    - AbstractGlobalExceptionHandler -- already handles all exception types

  Module Placement:
    - Entities      --> common
    - Services/APIs --> raservice
    - GUI pages     --> gui

  STATUS: *** IMPLEMENTED ***

  PHASE 3: REVOCATION MANAGEMENT                         [Size: L] [HIGH]
================================================================================

  Goal: Full revocation lifecycle + CRL generation + OCSP responder

  +-----------------------------------------------------------------------+
  | NEW TABLES                                                            |
  +-----------------------------------+-----------------------------------+
  | certificate_revocations           | certificate_id FK,                |
  |                                   | reason_code (RFC 5280),           |
  |                                   | revocation_time, revoked_by       |
  +-----------------------------------+-----------------------------------+
  | crl_entries                       | crl_number, this_update,          |
  |                                   | next_update, crl_blob, is_delta   |
  +-----------------------------------+-----------------------------------+

  RFC 5280 Revocation Reasons:
    0 = unspecified
    1 = keyCompromise
    2 = cACompromise
    3 = affiliationChanged
    4 = superseded
    5 = cessationOfOperation
    6 = certificateHold (suspension)

  APIs:
    POST /api/ra/certificates/{serial}/revoke    -- revoke with reason
    POST /api/ra/certificates/{serial}/suspend   -- certificateHold
    POST /api/ra/certificates/{serial}/unsuspend -- remove hold
    GET  /api/ra/crl/current                     -- download CRL
    POST /api/ra/ocsp                            -- OCSP responder (RFC 6960)

  New Quartz Jobs:
    - CrlGenerationJob            -- scheduled CRL generation
    - ExpiredCertificateCleanupJob -- mark expired certs

  Reuse:
    - CaProperties (already has crlDistributionPoint, ocspUrl)
    - BouncyCastle (already present for CRL/OCSP generation)
